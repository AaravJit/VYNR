# Backend: authoritative economy service

The Node server in `server/` now has two parts. One is the recognition proxy, which holds the AI key and the cost limits. The other is the economy service, which handles accounts, VYNR Credits (VC), collectibles, crates, the market, progression and entitlements. Both run in one process and keep separate SQLite files.

## Why the stack stayed the same

The existing server already uses `node:sqlite` with `BEGIN IMMEDIATE` transactions, which serialise writers. Every economy invariant depends on that: no double spend, one owner per collectible, idempotent retries. SQLite in WAL mode on a persistent volume is enough for one host and has no extra dependencies.

It does not scale across hosts. Before VYNR runs more than one server instance, move the economy store to Postgres with `SERIALIZABLE` transactions or `SELECT … FOR UPDATE`. The store already keeps all SQL in one class, so the port is contained. The phone's local SQLite stays a cache of the player's own game and is never authoritative for VC or ownership.

## Modules

| File | Responsibility |
| --- | --- |
| `economy/db.ts` | Versioned migrations with `up` and `down`, table constraints (`CHECK balance >= 0`, one active listing per collectible, unique idempotency keys) |
| `economy/store.ts` | Every economy operation, each in one transaction. Ledger-only VC movement, minting, provenance, invariant checks |
| `economy/config.ts` | Tunable economy: rewards, crates and pools, odds, market bounds, cosmetics, seasons, achievements. Validated at startup |
| `economy/catalog.ts` | Server copy of the curated catalog (`shared/catalog.json`, generated by `scripts/sync-shared.mjs` and checked by a drift test) |
| `economy/routes.ts` | HTTP API, validation, bearer auth, per-account write rate limits, feature flags |
| `economy/billing.ts` | Entitlement states, Apple and Google state mapping, verifier interface (refuses without credentials) |
| `scripts/simulate-economy.ts` | Economy simulation using the real store |

## Data model (summary)

- **accounts:** anonymous, random id. Optional handle and public profile. Profile settings (showcase, environment, frame, title).
- **tokens:** SHA-256 of 256-bit bearer tokens.
- **wallets and ledger:** each balance change writes one ledger row with the balance after it. Balance always equals the sum of the ledger.
- **recognitions:** candidates of a cloud answer made for an account. A discovery claim uses one, once, within 30 minutes.
- **discoveries:** verified real-world discoveries. Separate from inventory; selling or scrapping never removes one.
- **collectibles:** VYNR id, catalog vehicle, serial number per vehicle, cosmetic colour, edition, original acquisition (discovered, unboxed, showroom), current owner, burned state.
- **ownership_events:** full provenance (discovered, unboxed, showroom, sale, scrapped, account deleted).
- **crate_openings, listings, sales, wishlist, watchlist, idempotency, audit_events.**
- **achievement_claims, season_progress, season_claims, owned_cosmetics, entitlements, blocks, reports.**

There are no VINs, plates, owner identities or locations anywhere.

## API

All responses are JSON. Writes need `Authorization: Bearer <token>`. Crate opening, the showroom, scrapping, listing and buying also need an `Idempotency-Key`. Feature flags (`FEATURES`) switch the crates, market, seasons, social and subscriptions groups off; a disabled route returns `404 feature_disabled`.

| Group | Endpoints |
| --- | --- |
| Public | `GET /v1/config` (crates with full odds, prices, fee, cosmetics, seasons, achievements, Black benefits), `GET /v1/crates/:id/odds`, `GET /v1/market/listings`, `GET /v1/market/sales/:vehicle`, `GET /v1/collectibles/:id`, `GET /v1/profiles/:handle` |
| Account | `POST /v1/account`, `DELETE /v1/account`, `GET /v1/account/export`, `GET /v1/me`, `GET /v1/wallet/ledger` |
| Discovery | `POST /v1/recognize` (with a token, the response gains `recognitionId`), `POST /v1/discoveries`, `GET /v1/discoveries`, `GET /v1/inventory`, `POST /v1/collectibles/:id/scrap` |
| Crates | `POST /v1/crates/:id/open`, `GET /v1/crates/:id/pity`, `GET /v1/crates/openings/unseen`, `POST /v1/crates/openings/:id/seen`, `POST /v1/showroom/:vehicle` |
| Market | `POST /v1/market/listings`, `DELETE /v1/market/listings/:id`, `POST /v1/market/listings/:id/buy`, wishlist and watchlist `GET`/`PUT`/`DELETE` |
| Progression | `GET /v1/achievements`, `POST /v1/achievements/:id/claim`, `GET /v1/seasons/:id`, `POST /v1/seasons/:id/tiers/:tier/claim`, `POST /v1/cosmetics/:id/buy` |
| Social | `PUT /v1/profile`, `POST`/`DELETE /v1/blocks/:handle`, `POST /v1/reports` |
| Subscriptions | `GET /v1/entitlements`, `POST /v1/entitlements/verify`, `POST /v1/billing/{apple,google}/notifications` (both return `503 billing_not_configured` until store credentials exist) |

## Operations

- **Configuration:** `ECONOMY_STATE_FILE`, `FEATURES`, `ACCOUNTS_PER_IP_PER_DAY`, `ECONOMY_WRITES_PER_MINUTE`, `RATE_PER_INSTALL_PER_DAY_BLACK` (see `server/.env.example`). The economy config is validated at startup, and the server refuses to start if it is invalid.
- **Migrations** run automatically at startup, each in its own transaction. Never edit a shipped migration; add a new one.
- **Rollback:** restore the most recent backup to a copy, call `rollback(db, targetVersion)` on the copy, verify it, then swap. Never roll back a live database that has accepted writes under the newer schema without a backup.
- **Backups:** SQLite online backup (`VACUUM INTO` or `sqlite3 .backup`) every hour to object storage. Keep 7 days of hourly and 30 days of daily copies. Test a restore before launch.
- **Observability:** request logs carry method, path, status and duration only. `audit_events` records every economy action with random ids. `store.checkInvariants()` and `store.totals()` belong behind an operator-only health check. Alert on any invariant failure, on VC minted per day beyond the simulation's range, and on spend-ceiling hits.
- **Privacy:** account deletion removes tokens, profile, discoveries, recognitions, wishlist, blocks, reports by the player, cosmetics and season progress. It burns the player's collectibles and cancels their listings. Ledger and provenance keep only the random account id. Export returns everything the server holds for the account.
- **Secrets:** API keys and future store credentials live only in server environment variables.
